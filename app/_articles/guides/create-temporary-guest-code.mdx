## Quick Answer

Create a temporary guest code from the lock app, give it a clear name, set a start time before the guest needs entry, set an end time after the last reasonable access window, save it, and test it at the keypad before the guest arrives. For short-term rentals, make the code active 1 to 2 hours before check-in and expire it at 11:59 PM on checkout day unless your local policy requires a tighter cutoff.

The biggest mistake is setting expiration to midnight on the checkout date. Many systems interpret 12:00 AM as the beginning of that day, which can make a code expire too early. If the guest should have access through March 18, use March 18 at 11:59 PM or March 19 at 12:00 AM.

## When Temporary Codes Make Sense

Temporary codes are best for guests, cleaners, contractors, pet sitters, and family visits where access should end automatically. They are safer than shared permanent codes because every person or booking gets a unique credential with a defined window.

They are also easier to audit. If "Smith booking March 15-18" unlocks the door, you know which stay or task caused the access event. If everyone uses the same code, the access log is much less useful.

For one-time deliveries or very short visits, use one-time codes if your lock supports them. For recurring service, use a schedule instead of creating a new code every week.

## Choose the Access Window

Set the start time based on real arrival behavior, not only the written check-in time. A guest with a 3:00 PM check-in may arrive at 2:40 PM. A contractor scheduled at 10:00 AM may reach the door a few minutes early. Starting the code 1 to 2 hours early usually prevents support calls without creating meaningful extra risk.

The end time depends on the user type. Guests often need a buffer for late checkout, forgotten items, or travel confusion. Contractors usually need a tighter same-day window. Cleaners may need recurring access on specific days and hours.

| User type | Practical start | Practical end |
|---|---|---|
| Airbnb or vacation guest | 1 to 2 hours before check-in | 11:59 PM on checkout day |
| Contractor | 15 to 30 minutes before appointment | End of workday |
| Cleaner | Scheduled service window | Same day, or recurring schedule |
| Neighbor or pet sitter | Before first expected visit | After final expected visit |

## Create the Code

Most apps follow the same flow:

1. Open the lock app and select the correct door.
2. Go to `Users`, `Codes`, `Access`, or `Guests`.
3. Choose `Add user`, `Add code`, or `Guest access`.
4. Select temporary, scheduled, or guest access.
5. Enter a descriptive name.
6. Generate or enter a PIN.
7. Set the start date and time.
8. Set the end date and time.
9. Save and wait for the lock to sync.

Use names that explain the access later. "Airbnb - Smith - Mar 15-18" is better than "Guest 2." For contractors, include the task: "Plumber - kitchen sink - Mar 15."

Random generated PINs are safer than cute custom numbers. If you use a custom code for guest convenience, avoid repeating the same code across bookings.

## Test Before Sending

Testing is the difference between a smooth self-check-in and a late-night support call. If possible, test the code 12 to 24 hours before arrival. Confirm that the code appears as active or scheduled in the app, then try it on the keypad when the start window has begun.

For remote properties, use the lock's status and audit log if you cannot physically test. On hub-based locks, confirm the hub is online and that the code shows as synced, not just saved in the app.

If the test fails, delete the code and create a new one with an immediate start time. Do not keep editing a failing code if the guest is arriving soon; a clean new code is faster and easier to explain.

## Send Clear Instructions

Give the guest the code, the exact active window, the timezone, and the keypad behavior. Some locks require pressing a checkmark, lock button, or pound key after the PIN. Others unlock automatically after the final digit.

A concise message works best:

```text
Your door code is [CODE].
It is active from [START DATE/TIME/TIMEZONE] to [END DATE/TIME/TIMEZONE].
Wake the keypad, enter the code, then press [button if required].
If it does not unlock, send me a photo of the keypad message or call [number].
```

Do not send the same message thread to future guests with old codes still visible. Past access details are security data.

## Common Problems

If the guest says the code does not work, first check time. Is the code active yet? Has it expired? Is the timezone correct? Then check lock status. If the lock is offline, a newly created code may not have reached the keypad, although existing local codes may still work.

Next, verify entry format. Guests may include spaces, press the wrong final button, or confuse similar digits. If you suspect confusion, create a new code and send a short video or photo of the keypad instructions.

If a code remains active after checkout, delete it manually and review your settings. Some locks keep expired codes visible but inactive; others require manual cleanup. For rentals, review active codes at least weekly during busy season.

## Security Rules

Use one unique code per guest or job. Do not reuse the same "cleaner" code for unrelated workers unless they are part of the same trusted service. Delete or expire codes as soon as the need ends.

Keep a backup access method. Temporary codes are only useful if the lock has power, the keypad works, and the code has synced. A physical key, owner app access, or emergency contact prevents a small code issue from becoming a lockout.

For short-term rentals, remember that a smart lock does not make an illegal rental legal. Local rules, guest registration, fire safety, and insurance obligations still apply.
