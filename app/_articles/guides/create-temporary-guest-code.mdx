## Temporary Codes Need a Clear Window

A temporary smart lock code is useful because it ends without another manual cleanup step. That only works if the start time, end time, timezone, and lock sync are correct. A code that starts too late creates a support call. A code that expires too early can lock out a guest. A code that never expires becomes a permanent credential by accident.

Use temporary codes for short-term guests, contractors, pet sitters, neighbors, and service visits. Use recurring schedules for cleaners or regular vendors. Use one-time codes for deliveries if the lock supports them. Avoid giving anyone the master code just because it is faster.

## Avoid the Midnight Expiration Mistake

Many access problems come from misunderstanding midnight. If a checkout is March 18 and the code ends at March 18, 12:00 AM, some systems treat that as the very beginning of March 18. The guest may lose access before checkout morning.

If the code should work through checkout day, use a clear late-day time such as March 18 at 11:59 PM, or use March 19 at 12:00 AM if the app wording makes that easier to understand. For contractors, a tighter same-day end time is usually better. For cleaners, a recurring window such as Tuesdays from 10:00 AM to 2:00 PM is cleaner than a permanent shared code.

## Name the Code So It Explains Itself

Good names make access logs useful. "Airbnb - Smith - Mar 15-18" or "Plumber - kitchen sink - Mar 15" tells you why the code exists. "Guest 2" does not. If you manage multiple doors, include the unit, door, booking, or task in the name.

Use a random PIN when possible. If you choose a memorable number for guest convenience, do not reuse it across bookings. Reused guest codes weaken the log and make it harder to prove who had access after a complaint or claim.

## Create and Sync the Code

Most apps place temporary access under users, guests, access codes, or keypad codes. Select the correct lock, create a new guest or code, choose temporary or scheduled access, set the active window, save, and wait for the app to show that the code has reached the lock.

That last part is important. On Wi-Fi locks, sync may be quick. On hub-based, Z-Wave, Zigbee, or sleeping battery locks, the app can show a code before the lock has actually received it. If the guest is arriving soon, wake the keypad, check the hub, or send a lock command to confirm the lock is communicating.

## Test Before You Send It

For local properties, test the code at the keypad after the start window begins. For remote properties, check that the app shows the code as synced and review the audit log or device status if physical testing is not possible. If a code fails during testing, delete it and create a fresh one rather than editing the same failing entry repeatedly.

Do not send the code until you know it is active or scheduled correctly. A short delay before sending is better than a guest discovering the problem at the door with luggage in hand.

## Send Instructions That Prevent Guesswork

Tell the guest the PIN, active window, timezone, and keypad behavior. Some locks require a checkmark, lock button, or pound key after the digits. Others unlock after the final digit. If the keypad sleeps, explain how to wake it.

Keep the message short and avoid forwarding old code threads. Past access details are security data. For rentals, include a backup contact and ask the guest to report the exact keypad message if access fails. That is more useful than "it doesn't work."

## Handle Problems Without Creating More Risk

If a guest says the code does not work, check time and timezone first. Then check whether the lock is online and whether the code is synced. Confirm the entry format and final button. If you need to issue a replacement, create a new code with a clear name and delete the failed one after the guest is inside.

Keep a backup path for urgent cases: physical key, local manager, owner app access, or emergency code. A temporary code is only as good as the lock's power, keypad, and communication state.

After checkout or job completion, verify the temporary code expired or delete it manually. Some apps keep expired codes visible but inactive; others require cleanup. During busy rental periods, review active codes at least weekly.
