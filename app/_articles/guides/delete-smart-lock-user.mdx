## Removal Is More Than Deleting a PIN

A smart lock user may have a keypad code, app key, fingerprint, schedule, hub permission, or access created by a property-management integration. Removing only the visible PIN can leave another path open. Treat user removal as a credential audit, not a housekeeping click.

Delete access immediately when a guest checks out, a contractor finishes, an employee leaves, a roommate moves out, a phone with app access is lost, or there is any suspected compromise. For ordinary cleanup, review old temporary codes, duplicate users, inactive app invites, and service-provider entries every few months. If you cannot explain why a credential exists, remove it.

## Find Every Place the User Has Access

Start in the lock app, but do not stop there if the lock is connected to a hub or platform. Z-Wave and Zigbee locks may be managed from SmartThings, Hubitat, Home Assistant, or another lock-code manager. Apple Home, Google Home, Alexa, or a property-management system may also grant app-level control or recreate codes through automation.

Look for the person's PIN, app invite, fingerprint, recurring schedule, guest role, and any group membership. If a cleaner, vendor, or staff member shares a team code, consider replacing the shared credential with named access so future removal is cleaner.

## Remove and Verify

In most apps, open the correct lock, go to users, access, codes, guests, or fingerprints, select the person or credential, and choose delete, remove, revoke, or the trash icon. Wait for the app to show that the change has synced to the lock. For keypad-only locks, use the model-specific programming sequence and make sure you are deleting the correct user slot.

Verification is the important step. Enter the old PIN at the keypad. It should fail. If the user had app access, confirm the lock no longer appears for that account or can no longer be controlled. For former staff, guests, or anyone removed for security reasons, do not assume app deletion worked until the door proves it.

## If the Old Code Still Works

If the removed code still unlocks the door, the change probably did not reach the lock. Wait briefly and test again, then check battery level, hub status, Wi-Fi, and whether the app shows a pending sync. If the door is high-risk, remove the code directly at the keypad if your model supports it.

For urgent removals, changing the master or programming code and auditing the full user list may be faster than chasing one stubborn entry. A factory reset should stay as a last resort because it removes settings, schedules, calibration, integrations, and all current users. Use it when administrator access is lost, the lock was inherited with unknown users, or there has been a serious compromise.

## Keep a Record for Shared Properties

For homes, a clean user list may be enough. For rentals, offices, and managed properties, record when access was removed and why. A short note such as "Cleaner code removed after service contract ended, tested failed at keypad, May 9" can answer questions later.

Access logs vary by brand. Some show a deletion event; others only show that the user no longer exists. If the removal relates to a dispute, incident, or claim, export logs before making more changes.

## Build Removal Into the Access Process

Every new code should have an expected end date or review date. Temporary access should expire automatically, but still needs review. Permanent access should be limited to people who truly need it. For offices, tie lock access to the same offboarding checklist as email and software accounts. For rentals, review codes after every checkout cycle during busy season.

The best access list is short and explainable. Every active entry should have an owner, a reason, and a current need.
