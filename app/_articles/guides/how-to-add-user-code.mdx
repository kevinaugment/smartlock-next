## Add Access With an End in Mind

Adding a user code is easy. Adding the right kind of access is the part that matters. A family member, tenant, cleaner, contractor, guest, and emergency contact should not all receive the same permanent PIN. Good access management starts by deciding who needs entry, when they need it, and how you will remove it later.

Use one unique code per person or purpose. Shared codes feel convenient until something goes wrong and the access log cannot tell you who entered. Unique codes also let you remove one person's access without changing everyone else's.

## Choose the Right Access Type

Permanent access fits primary residents, long-term tenants, and trusted administrators. Temporary access fits guests, contractors, and short visits. Recurring schedules fit cleaners, dog walkers, and staff who only need access on certain days or hours. One-time codes are useful for deliveries if your lock supports them.

If the lock supports app keys, decide whether the person actually needs app control. Some app roles may show lock status, logs, or settings. A keypad PIN is often enough for guests and vendors, while app access should be reserved for people who need ongoing management or remote control.

## Pick a Code That Will Not Create Trouble Later

Use the longest practical PIN the lock supports, usually 6 to 8 digits. Avoid repeated digits, birthdays, street numbers, phone endings, and reused guest codes. For managed properties, store codes in a password manager or property-management system rather than old text threads or loose notes.

Name the user clearly. "Cleaner - Tue morning" or "Guest - Lee - May 12-15" is better than "Guest 3." Names that include the purpose or end date make future cleanup much easier.

## Create the User and Wait for Sync

Most apps place new users under users, access, access codes, keypad codes, or guests. Select the correct lock, create the user, enter the PIN, choose the schedule, save, and wait for the app to confirm the change reached the lock.

Do not confuse "saved in the app" with "active at the door." Battery locks may sleep. Hub-managed locks may queue changes. If the app hangs on sending, wake the keypad, move closer, check the hub, or send a lock command to confirm communication before creating duplicates.

For keypad-only programming, use the lock's manual for the exact command sequence and record the slot afterward. Some locks delete by slot rather than by code, so documentation prevents future mistakes.

## Test Before Sharing

Enter the new PIN at the keypad while another access method is available. Press the final lock, checkmark, or pound button if the model requires one. The lock should unlock cleanly without repeated attempts. If the code fails, confirm the schedule has started, the lock is online, and the PIN was entered exactly.

For remote properties, use the app's sync state and audit log if physical testing is impossible. If the code is for a same-day arrival, keep a backup code ready until the first entry succeeds.

Only share the code after it is active or scheduled correctly. Include the access window, timezone, and keypad behavior so the user is not guessing at the door.

## Avoid Common Access Mistakes

Do not make every user permanent. Do not reuse one contractor or guest code across unrelated people. Do not give the master or programming code to someone who only needs entry. Do not keep failed test codes or duplicate users around after setup.

Also watch code limits. Many locks support fewer codes than the app interface suggests, especially through hubs. Duplicate entries and forgotten expired users can fill the lock and prevent a new guest code from syncing when you need it.

## Review and Remove

Adding access should include a removal plan. Temporary codes should expire automatically, but they still deserve review. Permanent codes for former roommates, employees, vendors, and guests should be deleted immediately when the need ends.

For homes, review the list whenever people move in or out. For rentals, review after each checkout cycle. For small offices, tie lock access to the same onboarding and offboarding routine as software accounts. A healthy user list is short enough that every entry has a clear owner and reason.
