## Share the Smallest Useful Permission

Secure access sharing means giving the person enough entry to solve the real need and no more. A guest usually needs a temporary PIN. A cleaner may need a recurring schedule. A household member may need a normal user code. Admin access should be reserved for someone allowed to manage users, settings, and recovery.

Never share the master or programming code as a shortcut. It is difficult to revoke cleanly and may let someone add users, change settings, or blur the access record. If someone only needs to open the door, give them unlock-only access.

## Make Every Credential Traceable

Every person or role should have a unique code or app invitation. Shared codes make logs vague and cleanup harder. If four people know one code, you cannot tell who entered, and you have to rotate the code for everyone when one relationship ends.

Name access entries so they still make sense later: "Cleaner Tue 9-1," "Guest Chen May 12-15," or "Electrician panel work." For rentals, create a new code for every booking instead of recycling memorable codes.

## Time-Limit Access by Default

Temporary access should be the default for guests, contractors, vendors, and short visits. Start the code shortly before arrival and end it after the last reasonable access window. For recurring service providers, use scheduled access instead of a permanent all-day code.

Permanent access should be rare and intentional. If you cannot explain why a permanent code exists, remove it. For co-owners or managers with app access, confirm the role before sending the invitation; user, guest, and admin roles are not interchangeable.

## Send Less, But Make It Clear

Share the code, active window, timezone, door name, and keypad behavior. Some locks require a checkmark, lock button, or pound key after the digits. Avoid forwarding old message threads that expose previous codes. Do not post codes in group chats with people who no longer need access.

For higher-risk doors, use a password-manager share, encrypted message, or phone call instead of plain text. Ask the person to confirm receipt, but do not encourage screenshots or long-term storage for temporary access.

## Revoke and Review

Remove access when the stay ends, the work is complete, a staff member leaves, a phone is lost, or trust changes. For urgent removals, delete both app access and PIN access, then test that the old code no longer works.

Access logs are useful for operations and investigations, but they should not become casual surveillance. For staff, tenants, or commercial users, make the policy clear: what is logged, why it is logged, and who can review it.

Keep one reliable backup path, such as a physical key, owner app access, trusted local contact, or documented emergency code. For rentals and offices, write this down so recovery does not depend on one person's memory.
