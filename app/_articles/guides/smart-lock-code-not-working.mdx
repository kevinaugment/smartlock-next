## First Decide Whether One Code Failed or All Codes Failed

A single rejected PIN usually points to that user's code, schedule, expiration, or sync state. If every code fails, look at battery level, keypad response, lockout mode, or hardware. This distinction prevents wasted resets and avoids deleting working access.

Open the app and confirm the exact digits, active window, and sync state. A code can appear in the app while still waiting to reach the lock. If it was just created, wake the keypad or send a status command, then wait for the lock to confirm the update.

## Check Time, Timezone, and Expiration

Temporary and recurring codes fail when the current time is outside the allowed window. Check start date, end date, days of week, active hours, and timezone. Midnight is a common source of mistakes: 12:00 AM on the checkout date may mean the beginning of that date, not the end.

If a code should work through a checkout day, use a clear end time such as 11:59 PM that day, or 12:00 AM the following day if the app's wording supports it. If the lock or hub timezone is wrong, scheduled codes can be rejected even when the app screen looks reasonable.

## Enter the Code Like the Lock Expects

Some keypads unlock after the final digit. Others require a checkmark, lock button, or pound key. Enter slowly enough that each digit registers. If one digit does not beep, lights unevenly, or double-registers, clean the keypad and avoid using that digit until the keypad is repaired.

Repeated wrong attempts can trigger a temporary lockout. If the keypad stops responding after several failures, wait for the timeout rather than continuing to press buttons.

## When No Code Works

If every PIN fails, use another legitimate access method first: app unlock, fingerprint, physical key, or emergency power if available. Once inside, replace weak batteries with a fresh matching set. Low batteries can make keypads lag, reject input, or accept a code without moving the motor reliably.

Then check whether the lock is online. Wi-Fi locks need a stable connection for new code updates. Bluetooth locks may need the phone nearby. Z-Wave and Zigbee locks depend on the hub path. If a code was created while the lock was offline, delete it and create a fresh one after communication is restored.

## Code Slots and Duplicate Users

Many locks have a finite number of code slots. If the lock is full, a new code may fail to sync, stay pending, or behave unpredictably depending on the app and hub. Delete old guests, test users, and expired service codes before adding another user.

Avoid duplicate PINs. Some systems reject them, while others allow confusing duplicates that make logs less useful. A clean user list makes code failures much easier to diagnose.

## When It Is Not a Code Problem

If the keypad accepts the PIN but the bolt does not move fully, the issue is motor strain, alignment, or battery power rather than the code. If app unlock works but the keypad never registers one or more digits, suspect keypad hardware or moisture. If a newly created guest code fails while older local codes still work, suspect sync or connectivity.

Do not factory reset for an ordinary code failure. Reset only when administrator access is lost, user records are corrupted, or you inherited a lock with unknown credentials.
