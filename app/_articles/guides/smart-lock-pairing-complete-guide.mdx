## Pairing Fails for Practical Reasons

Most smart lock pairing failures are not mysterious. The lock may still belong to an old hub, the batteries may be weak, the phone may be too far away, the Wi-Fi band may be unsupported, the mesh may not reach the door, or the Matter setup code may be missing. Fix those basics before repeating the same setup attempt.

Use fresh batteries, keep the phone or hub near the lock during first enrollment, and save the QR code, setup PIN, DSK, or programming label before mounting covers over it. If the lock was previously paired, remove it from the old app or hub. If that system is gone, reset pairing state before adding it to the new one.

## Match the Setup Path to the Radio

Wi-Fi locks usually pair through the manufacturer's app and often require a 2.4 GHz network. Bluetooth locks need the phone close to the door and may need location or Bluetooth permissions. Zigbee and Z-Wave locks join through a hub. Matter locks use a QR code or setup PIN through an ecosystem app, and Thread-based Matter locks also need a working Thread border router.

Do not rely on product-family names alone. The same lock line may have Wi-Fi, Z-Wave, Zigbee, Bluetooth, or Matter variants. Check the exact model label and manual before choosing the setup path.

## Clear Old Enrollment

Stale enrollment is one of the most common causes of failed pairing. A lock can appear new while still remembering an old hub. For Z-Wave, run exclusion before inclusion, even if you think the lock is factory fresh. For app-based locks, remove the device from the old account if possible.

If you cannot access the old system, factory reset may be appropriate, but record anything you need to recreate first. Resetting clears users, schedules, pairing, and sometimes calibration.

## Solve Signal Before Software

Pair close to the controller first, then test at the installed door. Metal doors, brick, concrete, appliances, mirrors, electrical panels, and long hallways can weaken signal. Battery locks usually do not repeat mesh traffic, so another battery lock is not a repeater.

For Wi-Fi, confirm signal at the door and avoid captive portals or enterprise networks unless supported. For Zigbee and Z-Wave, add powered repeaters or move the hub. For Thread, confirm the border router is online and close enough to build a stable mesh.

## Know When Pairing Mode Actually Started

Pairing mode usually times out. Confirm the lock is showing the blinking, beeping, or app prompt described in the manual. Some locks require a program button. Others require the master code first. If the app cannot find the lock, the lock may never have entered pairing mode.

After successful pairing, do not stop at "device added." Test app lock/unlock, keypad code creation, status reporting, battery reporting, auto-lock, and any voice or automation feature you plan to use. Create and delete one test user code to confirm credential sync works before depending on it for guests or staff.

## When to Contact Support

If pairing still fails after fresh batteries, close range, correct protocol, old enrollment cleanup, hub reboot, and one clean reset, gather the lock model, hub model, app name, setup code type, and the exact step where setup fails. That information is more useful to support than another blind retry.
