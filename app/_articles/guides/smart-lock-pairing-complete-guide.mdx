## Quick Answer

Smart lock pairing works best when the lock is fresh, close to the phone or hub, powered by new batteries, and not still enrolled in another system. Before retrying, remove stale device records, reset pairing mode, confirm the protocol, and keep the lock near the controller until setup finishes.

Most pairing failures are not mysterious. They come from wrong Wi-Fi band, weak mesh signal, old hub enrollment, missing Matter code, Z-Wave security setup, or a lock that never entered pairing mode.

## Before Pairing

Install the lock mechanically first, but test pairing before final cleanup. Use fresh batteries. Keep the phone, hub, or controller near the lock. Save the QR code, setup PIN, DSK, or programming label before mounting covers over it.

If the lock was previously paired, remove it from the old app or hub. If you cannot access the old system, factory reset the lock before adding it to the new one. A lock can look available while still rejecting new enrollment because it believes it already belongs somewhere.

## Choose the Right Setup Path

| Protocol | Pairing path | Common failure |
|---|---|---|
| Wi-Fi | Manufacturer app to 2.4 GHz network | Wrong band or password |
| Bluetooth | Phone close to lock | Phone too far or Bluetooth permission blocked |
| Zigbee | Hub inclusion mode | Hub too far or weak mesh |
| Z-Wave | Hub inclusion plus security code | Old enrollment or DSK issue |
| Matter | QR code or setup PIN through ecosystem app | Wrong commissioner or border router issue |

If you are not sure which protocol the lock uses, check the model label and manual before starting. Similar product names can have different radios.

## Pair Wi-Fi Locks

Wi-Fi locks usually pair through the manufacturer's app. Confirm the network is 2.4 GHz if the lock requires it, and avoid captive portals or enterprise Wi-Fi unless the product specifically supports them.

Stand near the lock, allow Bluetooth and location permissions if the app requests them, scan the QR code or enter the serial number, and wait for the app to confirm the lock has joined the network. If it fails, retype the password, move closer to the router, and temporarily separate 2.4 GHz and 5 GHz SSIDs if band steering confuses setup.

After pairing, test app lock/unlock and keypad operation before adding automations.

## Pair Zigbee Locks

Put the hub in add-device or inclusion mode first, then put the lock into pairing mode. Keep the lock close to the hub for initial enrollment, even if the door is farther away later.

If the hub cannot find the lock, reset the lock's pairing state and try again near the hub. After successful pairing, move the hub back or strengthen the mesh with powered Zigbee devices between the hub and lock. Battery locks usually do not repeat mesh traffic, so do not rely on another lock as a repeater.

If commands fail after pairing, the lock may be at the edge of the mesh. Improve signal before adding schedules and user codes.

## Pair Z-Wave Locks

Z-Wave locks often need exclusion before inclusion, even when they look new. Run exclude/remove device from the hub, trigger the lock's Z-Wave action, then start inclusion again.

For S2 security, be ready to enter the DSK or scan the QR code. If the DSK label is hidden under a cover, find it before starting. Do not accept insecure pairing for an exterior lock unless you understand the tradeoff.

If pairing succeeds but control is unreliable, run a Z-Wave repair after the lock is installed and make sure there are powered Z-Wave repeaters near the entry path.

## Pair Matter Locks

Matter pairing uses a QR code or setup PIN through Apple Home, Google Home, Alexa, SmartThings, or another commissioner. For Thread-based locks, the ecosystem needs a working Thread border router. For Wi-Fi Matter locks, the Wi-Fi network must be supported by the device.

If the QR code will not scan, enter the setup code manually. If commissioning fails, reboot the phone, lock, and border router or hub, then retry with the phone on the same ecosystem account. If the lock was already added to one ecosystem, use the app's sharing or multi-admin process instead of factory resetting unless you want to start over.

## Fix Pairing Mode Problems

Pairing mode usually times out. If the app cannot find the lock, confirm the lock is actually blinking, beeping, or showing the pairing signal described in the manual. Some locks require holding a program button; others require entering the master code first.

If the lock will not enter pairing mode, remove batteries for a minute, reinstall, and try again. If it still refuses, check whether it is already paired or needs a factory reset.

## Improve Signal Before Troubleshooting Software

Many "pairing" problems are signal problems. Keep the first pairing close to the controller, then test at the installed door. Metal doors, brick, concrete, appliances, mirrors, and electrical panels can weaken radio signals.

For Wi-Fi, check signal at the door with a phone. For Zigbee and Z-Wave, add powered repeaters or move the hub. For Bluetooth setup, keep the phone within a few feet until setup finishes.

## After Pairing

Do not stop after the app says added. Test app lock/unlock, keypad code creation, status reporting, auto-lock, battery reporting, and any voice assistant or automation you plan to use.

Create one test user code and delete it. This confirms user-code sync works before you depend on it for guests or staff.

## When to Reset

Factory reset is appropriate when the lock was previously owned, the old hub is gone, the app shows corrupted setup, or repeated pairing attempts fail after exclusion/removal. Resetting clears users and settings, so record anything you need to recreate first.

If pairing still fails after reset, fresh batteries, close range, correct protocol, and hub reboot, contact support with the lock model, hub model, app name, and the exact step where pairing fails.
