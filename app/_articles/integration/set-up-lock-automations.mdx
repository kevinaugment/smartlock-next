Smart lock automations should remove repetitive work without creating unsafe surprises. Locking a door after it has been left unlocked is usually safe. Unlocking a door automatically based on location, motion, or a doorbell event needs more caution.

Start with simple, reversible automations and test them for several days before relying on them. A smart lock automation is part of your access plan, not a novelty routine.

## Start With Auto-Lock

Auto-lock is the most useful automation for most homes and rentals. Set the lock to secure itself after a reasonable delay when the door has been unlocked. Three to five minutes is often enough for a home entry door, while offices and rentals may need a different delay.

If the lock has a door position sensor, configure auto-lock to run only when the door is closed. Locking while the door is open can extend the deadbolt into empty space and create a jam when someone closes the door.

For door position issues, see [Door Sensor Not Working](/articles/installation/door-sensor-not-working).

## Be Careful With Auto-Unlock

Location-based unlock can be convenient, but it should include safeguards. Phone location can be wrong, delayed, or triggered while you are nearby but not actually at the door. Many platforms require confirmation before unlocking, and that is usually a good thing.

Use auto-unlock only if the lock still requires authentication or confirmation, or if the door is low risk. For exterior doors, rentals, and businesses, a notification with an unlock button is safer than silent automatic unlock.

## Useful Automation Patterns

| Automation | Safer default |
|---|---|
| Door left unlocked | Send alert, then auto-lock if door is closed |
| Last person leaves | Lock door, do not unlock on arrival without confirmation |
| Night routine | Lock exterior doors at a set time |
| Guest check-in | Use scheduled PINs, not broad unlock automations |
| Doorbell press | Notify with camera view and manual unlock option |

The best automations are narrow and predictable. Avoid routines that combine too many triggers, such as motion plus time plus location plus voice, until the simpler flow is proven.

## Platform Setup Notes

Apple Home, Google Home, Alexa, SmartThings, Home Assistant, and vendor apps all use different automation language, but the logic is the same: choose a trigger, add conditions, choose the lock action, and test the result.

For Apple Home and Matter setup, use [HomeKit vs Matter Smart Lock Setup](/articles/protocols/connect-lock-to-homekit). For doorbell-linked workflows, use [Smart Lock and Video Doorbell Integration](/articles/integration/doorbell-smart-lock-integration).

## Test Before Trusting

After creating an automation, test the normal case and the failure case. Does auto-lock run when the door is closed? What happens if the door is open? What happens if the internet is down? Does the platform notify you before unlocking? Does the app show the correct final state?

For rentals and businesses, document the automation and who can change it. Silent changes to lock routines can create support and liability problems.

## Final Recommendation

Automate locking before you automate unlocking. Keep humans in the loop for risky unlock actions. Use keypad codes and backup access for guests and tenants. A good automation should make the lock more predictable, not harder to explain.
