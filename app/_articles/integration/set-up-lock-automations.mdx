Smart lock automations should remove repetitive work without creating unsafe surprises. Locking a door after it has been left unlocked is usually safe. Unlocking a door automatically based on location, motion, or a doorbell event needs more caution.

Start with simple, reversible automations and test them for several days before relying on them. A smart lock automation is part of your access plan, not a novelty routine.

## Start With Auto-Lock

Auto-lock is the most useful automation for most homes and rentals. Set the lock to secure itself after a reasonable delay when the door has been unlocked. Three to five minutes is often enough for a home entry door, while offices and rentals may need a different delay.

If the lock has a door position sensor, configure auto-lock to run only when the door is closed. Locking while the door is open can extend the deadbolt into empty space and create a jam when someone closes the door.

For door position issues, see [Door Sensor Not Working](/articles/installation/door-sensor-not-working).

## Be Careful With Auto-Unlock

Location-based unlock can be convenient, but it should include safeguards. Phone location can be wrong, delayed, or triggered while you are nearby but not actually at the door. Many platforms require confirmation before unlocking, and that is usually a good thing.

Use auto-unlock only if the lock still requires authentication or confirmation, or if the door is low risk. For exterior doors, rentals, and businesses, a notification with an unlock button is safer than silent automatic unlock.

## Useful Automation Patterns

| Automation | Safer default |
|---|---|
| Door left unlocked | Send alert, then auto-lock if door is closed |
| Last person leaves | Lock door, do not unlock on arrival without confirmation |
| Night routine | Lock exterior doors at a set time |
| Guest check-in | Use scheduled PINs, not broad unlock automations |
| Doorbell press | Notify with camera view and manual unlock option |

The best automations are narrow and predictable. Avoid routines that combine too many triggers, such as motion plus time plus location plus voice, until the simpler flow is proven.

## Platform Patterns

Apple Home is strongest when the household already has a Home Hub and wants simple scenes such as "Good Night" or "Leave Home." It can be excellent for locking, notifications, and basic Matter workflows. For unlock actions, use confirmation and keep keypad or key backup available. If the lock setup path is unclear, start with [HomeKit vs Matter Smart Lock Setup](/articles/protocols/connect-lock-to-homekit).

Google Home and Alexa are useful for routines and voice control, but voice unlock deserves strict controls. Use PIN confirmation where the platform supports it, avoid unlock routines triggered by broad presence or motion signals, and test whether the command works when the internet is slow.

SmartThings, Hubitat, and Home Assistant can support deeper conditions, but deeper logic creates deeper failure modes. A rule that checks door state, time, presence, alarm mode, and lock state may be powerful, but each condition can be stale. For hub-based homes, pair automations with [Improve Smart Lock Connection Stability](/articles/protocols/improve-connection-stability).

Vendor apps are often the safest place for model-specific features such as auto-lock delay, keypad behavior, guest-code schedules, and battery alerts. Use ecosystem automations only after confirming what the lock itself already handles locally.

## Rental And Business Rules

For rentals, do not use location-based auto-unlock for guests. A guest may arrive with a different phone, bad reception, a dead battery, or no app installed. Scheduled PINs are safer, easier to explain, and easier to revoke. Use [Guest Code Planner](/calculators/guest-code) before a short-term rental relies on automation.

For businesses, every automation should have an owner. If an exterior door locks every night at 9 PM, someone should know who can override it and how exceptions are logged. If a staff door unlocks for a delivery window, the rule should expire automatically and appear in access logs.

For family homes, the best first automation is usually simple: alert when unlocked too long, lock at bedtime, and warn when batteries are low. Add arrival-based conveniences only after the basic routines are boring.

## Failure Cases To Test

Before trusting an automation, test these cases:

- Door open when auto-lock fires.
- Phone arrives near the home but the person does not enter.
- Internet is down but local keypad access is still needed.
- Hub or Home Hub restarts during the automation window.
- Manual thumbturn changes the lock state after the app last checked it.
- Guest code expires while a cleaner or contractor still needs access.
- Low battery delays or prevents a lock command.

If any failure creates a lockout or unexpected unlock, simplify the routine. A notification plus manual action is often better than a clever rule that cannot be explained at the door.

## Automation Acceptance Checklist

A lock automation is ready only when the normal case, failure case, and recovery path are documented. Record the trigger, conditions, action, owner, notification path, backup entry method, and how to disable the rule quickly. For managed properties, store that checklist with the turnover or facilities process, not only inside one user's app.

Use [Emergency Backup Planner](/calculators/emergency-backup), [Offline Resilience Scorecard](/calculators/offline-resilience), and [Door Compatibility Guide](/articles/guides/door-compatibility-guide) when automation affects real guests, tenants, staff, or exterior doors.

## Platform Setup Notes

Apple Home, Google Home, Alexa, SmartThings, Home Assistant, and vendor apps all use different automation language, but the logic is the same: choose a trigger, add conditions, choose the lock action, and test the result.

For Apple Home and Matter setup, use [HomeKit vs Matter Smart Lock Setup](/articles/protocols/connect-lock-to-homekit). For doorbell-linked workflows, use [Smart Lock and Video Doorbell Integration](/articles/integration/doorbell-smart-lock-integration).

## Test Before Trusting

After creating an automation, test the normal case and the failure case. Does auto-lock run when the door is closed? What happens if the door is open? What happens if the internet is down? Does the platform notify you before unlocking? Does the app show the correct final state?

For rentals and businesses, document the automation and who can change it. Silent changes to lock routines can create support and liability problems.

## Final Recommendation

Automate locking before you automate unlocking. Keep humans in the loop for risky unlock actions. Use keypad codes and backup access for guests and tenants. A good automation should make the lock more predictable, not harder to explain.
