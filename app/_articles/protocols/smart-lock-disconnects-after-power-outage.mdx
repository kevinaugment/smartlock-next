After a power outage, the lock itself is usually not the problem. Most smart locks run on batteries, so the keypad, thumb turn, and physical key can still work while the router, modem, hub, or Thread border router is coming back online. The app looks broken because the network path is still recovering.

Give the system time before resetting everything. A router may return in a few minutes, while a Zigbee, Z-Wave, or Thread network can take longer to rebuild routes and wake battery devices. If the lock is still offline after 10 to 15 minutes, work from the network outward instead of repeatedly removing lock batteries.

## What Usually Happens

When power drops, the modem, router, hub, repeaters, bridges, and border routers all go offline. The lock stays powered, but it loses the path that lets the app talk to it. When power returns, each layer has to restart in order: internet equipment first, then the smart-home controller, then powered repeaters, then battery devices.

That order matters. Battery locks often reconnect last because they sleep most of the time. Pressing the keypad or manually operating the lock can wake it, but it still needs a stable hub or router path before app control returns.

## Recovery Steps

Start by confirming local access. Try the keypad, thumb turn, or physical key. If local access works, you are dealing with connectivity, not a failed lock.

Next, check the internet equipment. Make sure the modem and router show normal status lights and that a phone or computer can use the network. If the internet is not back, fix that first.

Then check the smart-home hub, bridge, or border router. SmartThings, Hubitat, Home Assistant hardware, HomePod, Apple TV, Nest Hub, or a vendor bridge may need several minutes after power returns. If the hub still looks offline, unplug it for 30 seconds, plug it back in, and wait at least five minutes.

After the hub is stable, wake the lock by pressing a keypad button or manually locking and unlocking once. Give it a few minutes to rejoin. Only remove the lock batteries if the network is healthy and the lock still refuses to reconnect.

## Protocol Differences

Wi-Fi locks usually recover once the router and internet connection are stable. If they remain offline, check battery level and Wi-Fi signal at the door before starting a full reconnect flow.

Zigbee and Z-Wave locks depend on a mesh. Powered repeaters and plugs may need to return before the lock finds a good route. Z-Wave networks can also take longer when secure devices rebuild routes. If your hub offers a network repair tool, use it only after the powered devices are online.

Thread locks depend on a border router such as a HomePod mini, Apple TV, or supported smart display. If the border router restarts slowly or changes role, the lock may need extra time before the app shows the correct state.

## When It Is Not Just The Outage

If the lock goes offline after every outage, there is probably a design issue. Common causes include a hub plugged into an unreliable outlet, a router that reboots slowly, weak signal at the door, no powered repeaters near a mesh lock, or lock batteries that are too weak to reconnect reliably.

Repeated post-outage failures should be treated like a network resilience problem. Review [Improve Connection Stability](/articles/protocols/improve-connection-stability) and [Smart Lock Keeps Going Offline](/articles/protocols/smart-lock-keeps-going-offline) instead of only repeating the recovery steps.

## Prevention

Put the modem, router, and smart-home hub on a small UPS if the lock is important for rentals, offices, or emergency access. The lock already has batteries; the weak point is usually the network equipment. A UPS that keeps the router and hub running through short outages prevents many reconnect problems.

For mesh systems, keep at least one powered repeater near the door and on the same protected power path if possible. For rental or business use, document a backup entry method that does not depend on app control. The [Emergency Backup Planner](/calculators/emergency-backup) is useful for that.

## Final Check

Once the lock returns online, test app lock, app unlock, keypad unlock, and status reporting. If the app state is wrong, manually operate the lock once and let it resync. If the lock remains offline while local access works, the next place to investigate is signal quality, hub health, or firmware, not the deadbolt itself.
