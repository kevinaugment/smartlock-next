Zigbee locks can work well with Home Assistant, but they are not a plug-and-forget purchase. The coordinator, integration, repeaters, and exact lock model need to be chosen together. A lock that pairs easily in one setup can expose fewer controls, miss battery updates, or handle PIN codes poorly in another.

Start with the lock model, not the protocol label. Confirm whether the exact lock is well supported by ZHA or Zigbee2MQTT, then decide which integration you want to maintain. If you are still comparing Zigbee with Z-Wave, Thread, or Wi-Fi, use the [Protocol Selection Wizard](/calculators/protocol-wizard) before buying hardware.

## ZHA, Zigbee2MQTT, and Hub Bridges

ZHA is the simpler native path because it is built into Home Assistant and avoids another service. It is a good fit when the lock is supported cleanly and you want fewer moving parts. The limitation is device support: some locks expose only basic functions, and advanced code management can vary by model and firmware.

Zigbee2MQTT often gives more visibility into devices and exposes controls that are useful for troubleshooting. It can be the better path for users who are comfortable maintaining MQTT, reading device converters, and watching integration-specific behavior. The cost is complexity. If the lock is on a rental or main entry door, do not choose Zigbee2MQTT just because it sounds more powerful; choose it because the exact lock behaves better there.

A vendor hub bridge can make sense when the buyer wants the manufacturer's app as a fallback. The tradeoff is that Home Assistant may see only part of the lock's feature set. Matter bridge paths can help mixed-ecosystem households, but feature mapping for locks is still something to verify instead of assume.

## Coordinator and Repeater Planning

A lock is usually a sleepy battery device, not a repeater. It should have a strong route through powered Zigbee devices that stay awake. Place a reliable powered repeater between the coordinator and the door before pairing, especially if the door is exterior, metal, far from the coordinator, or separated by dense walls.

Good repeater candidates are powered plugs or modules known to route well. Avoid assuming every bulb or inexpensive device is a stable router for lock traffic. Keep the coordinator away from USB 3.0 noise and Wi-Fi routers, and test the lock in its installed location rather than on a desk near the coordinator.

Use the [Signal Strength Calculator](/calculators/signal-strength) and [Mesh Network Planner](/calculators/mesh-planner) to think through the physical path. The goal is not maximum device count. The goal is a small number of dependable routers placed where the lock actually needs them.

## Pairing and Code Management

Before trusting the lock, test more than lock and unlock. Verify battery reporting, jammed or failed-lock status, state refresh after manual operation, PIN creation, PIN deletion, temporary code behavior, and recovery after Home Assistant restarts. If the lock will be used on a rental or exterior door, document the fallback process before a guest or tenant depends on it.

Code management deserves special attention. Some locks expose clean code slots and names; others require awkward service calls or partial integration support. If your workflow depends on scheduled guest codes, staff codes, or turnover automation, prove that workflow locally before installing the lock in a property.

## Security and Access Controls

Do not expose Home Assistant directly to the internet just to control a lock. Use secure remote access, strong account controls, backups, and a recovery path that still works when an automation fails. For rentals, avoid giving guests app access when a temporary PIN code is safer and easier to revoke.

Zigbee can deliver strong battery life, but poor mesh quality still causes retries, missed status, and battery drain. If the lock starts behaving inconsistently, inspect the route, repeater quality, door alignment, and firmware before blaming Home Assistant itself.

The best Home Assistant Zigbee lock setup is deliberately boring: a supported lock, a stable coordinator, a known-good repeater near the door, tested code management, and a recovery plan. Anything less can still work, but it should not be treated as reliable access control until it has survived real use.
