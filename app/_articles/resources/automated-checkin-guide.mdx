## The Ideal Flow

1.  **Booking Confirmed**: Guest books on Airbnb.
2.  **Trigger**: PMS (e.g., Guesty) detects new reservation.
3.  **Code Generation**: PMS calls Lock API -> Generates unique PIN (last 4 digits of phone).
4.  **Communication**: Automated message sent to guest: "Welcome! Your code is 1234."
5.  **Activation**: Code becomes active at Check-In time (e.g., 3:00 PM).
6.  **Expiration**: Code is deleted at Check-Out time (e.g., 11:00 AM).

## 2026 Planning Notes

Use this page to narrow choices and frame the discussion, then verify the exact lock model, door prep, and deployment workflow that will be used in the field.

For guest or tenant access, always confirm offline keypad behavior, code rotation speed, and what happens if the internet or PMS integration is unavailable.

## How to Use This Reference

1. Confirm the exact door type, lock family, controller path, and operating environment you are designing for.
2. Eliminate options that fail the mechanical, compliance, offline-access, or lifecycle-cost requirements that matter most for this deployment.
3. Validate the final choice against the current manufacturer documentation and a test on the real door whenever the consequence of failure is high.
