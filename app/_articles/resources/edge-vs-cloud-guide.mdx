## The Brain Location

### Cloud Processing
*   **Input**: You type a code.
*   **Process**: Lock asks server "Is this right?"
*   **Risk**: Server down = Lock dumb. High latency.
*   **Example**: Old August Connect (bridges).

### Edge Processing (Local)
*   **Input**: You type a code.
*   **Process**: Lock checks internal memory "Is this right?"
*   **Benefit**: Instant, works offline, private.
*   **Example**: Schlage Encode, Level Lock.

## 2026 Planning Notes

Published range, battery, and interoperability numbers are planning inputs only. Walls, radio congestion, border routers, and firmware policy still change the field result materially.

Treat local radio health, border-router or hub placement, and fallback behavior during internet loss as first-class design inputs, not afterthoughts.

## How to Use This Reference

1. Confirm the exact door type, lock family, controller path, and operating environment you are designing for.
2. Eliminate options that fail the mechanical, compliance, offline-access, or lifecycle-cost requirements that matter most for this deployment.
3. Validate the final choice against the current manufacturer documentation and a test on the real door whenever the consequence of failure is high.
