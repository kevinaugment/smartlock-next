## Quick Answer

In New York City, smart locks do not make an illegal short-term rental legal. Treat them as operational tools for compliant stays: unique guest codes, clear host access policy, emergency access, and privacy-limited logs.

Start with the official NYC short-term rental registration rules before changing access workflows. Then use [Guest Code Planner](/calculators/guest-code), [Privacy Compliance Checker](/calculators/privacy-compliance), and [Audit Trail Guide](/articles/security/audit-trail-forensic-analysis) to document the operating model.

## NYC-Specific Smart Lock Risks

| Risk | Smart lock implication |
|---|---|
| Hosted-stay rules | Remote code delivery can look like unhosted operation if the listing is not compliant |
| Registration records | Access logs may support or contradict stay records |
| Guest privacy | Entry logs should be limited to security and operational needs |
| Emergency access | Backup access must exist for fire, safety, maintenance, and lock failure |

## Compliance Workflow for Hosts

1. Confirm the listing is lawful under NYC rules before optimizing check-in.
2. Use one code per reservation or monthly tenant, never shared permanent guest codes.
3. Set activation and expiration windows that match the lawful stay.
4. Keep host/admin codes separate from guest codes.
5. Retain access logs only as long as needed for security, disputes, or legal records.
6. Provide a lockout path that does not require the guest to install an app.

## What Not to Do

- Do not use smart locks to operate an unhosted short-term rental where that use is prohibited.
- Do not reuse one PIN for every guest.
- Do not monitor access patterns beyond legitimate security and operations.
- Do not remove physical emergency access.
